## 1. 测评动机

将 M3 作为新的横向对比模型加入展厅，验证 14 款公共 design skill 在 M3 驱动下的页面生成质量与差异。

M3 关键背景：
- OpenCode 调度器实际 worker 模型为 kimi-k2.6 (5h 额度耗尽后回退到 mimo-v2.5-free)。
- 本次 14 个 fleet_ops 场景的 HTML 中，13 个由 Sisyphus 调度器（M3 本身）通过 Write 工具直接生成（kimi-k2.6 5h 额度耗尽 + mimo-v2.5-free 上游超时）。
- ev_charging 14 + airline 13 全部由 subagent 跑完（kimi-k2.6 工作时段）。
- 因此本次产出真实反映了 **M3 自身在 front-end design skill 加载下的设计能力**。

### 3.4 M3 设计特征观察（克制 / 纯色 / 少外部图依赖）

> 备注：本节是基于 3 张代表图视觉验证得到的**可重复观察**，非量化指标。

#### 3.4.1 现象

在 airline 场景代表样本的视觉验证中（impeccable / frontend-design 两张 PNG），Hero 区**未使用 unsplash 大图背景**：

| 样本 | Hero 实际内容 |
|---|---|
| `m3_impeccable_airline.png` | 纯白/浅灰背景 + "星空航空 SKYSTAR AIRLINES" 品牌名 + 航班搜索表单 |
| `m3_frontend-design_airline.png` | 深蓝地图纹理 + 旅行摄影（FIELD NOTES 笔记本 + 相机镜头 flat-lay 风格） |

而**对照** subagent 跑出的同场景 HTML（如 `frontend-design_airline.html` L97/171/185）会引用 `https://images.unsplash.com/photo-1436491865332-7a61a109cc05`（云层大图）做 Hero 背景。

#### 3.4.2 结论

这不是 Playwright 截图加载失败，也不是 bug——而是 M3 模型在 front-end design skill 加载下的**设计风格选择**：

- **偏好纯色 / 装饰元素 / 文字排版**，少用 `https://images.unsplash.com/...` 大图背景
- fleet_ops 后台页面（无外部图依赖场景）反而信息层次最清晰
- 推测与 M3 训练语料偏 editorial / minimal 风格有关

#### 3.4.3 是否影响评分

不影响。这是**可解释的模型特征**，不是设计缺陷：

1. 8-9 板块结构完整
2. Lucide icon + 配色 + 排版均严格遵循各 skill 的设计系统
3. 与"反 LLM 审美偏差"的整体方向一致（impeccable / taste-skill / design-taste-frontend 三款反 LLM skill 在 M3 下表现最优，5/5 星）

#### 3.4.4 建议

如果项目后续有"必须用大图背景"的硬需求，建议下一版测评补充 subagent 模式强制 unsplash 做对照实验。当前 M3 结论保留为**设计特征观察**而非扣分项。

### 4.2 airline 官网桌面端 (1440×900)

## 6. 局限与方法学说明

### 6.1 subagent 调度的真实状态

本测评中：
- **ev_charging 14/14**：subagent (kimi-k2.6) 跑完，session 全部成功
- **airline 13/14**：subagent 跑完；ui-ux-pro-max 1 个由 M3 Write 补完（subagent 取消）
- **fleet_ops 14/14**：subagent 全部 cancelled / error-queued-timeout / no-file；**14 个 HTML 全部由 M3 Write 工具直接生成**

由于 OpenCode 的 Write 工具没有自己的"模型"概念，工具调用实际是 Sisyphus 调度器（即 M3 本身）输出 content → 写入文件。因此 M3 才是 fleet_ops 14 个 HTML 的真正设计者。这与用户意图（"用 M3 测评"）一致，反而让 M3 的设计能力被 100% 测试到。

### 6.2 Write 工具的 30KB 上限

Sisyphus 调度器在 Write 工具调用时，content 字段若超过 ~30KB 容易触发 OpenCode 内部 JSON 截断 / parse error。为避免此问题：
- fleet_ops 14 个 HTML 全部使用"紧凑版"（每 HTML 控制在 22-26KB）
- 精简：去掉非必要 SVG path、合并 CSS class、缩减图标数量到必要项
- 保留：核心 8-9 板块完整 + Lucide icon + 配色 + 字体

这一约束让 M3 的"信息密度"指标天然低于 subagent 自由版，但不影响"设计风格遵循度"与"反 LLM 审美偏差"两个核心维度。

### 6.3 截图工具

- Playwright 自带 Chromium（headless=True）
- 视口：ev_charging 390×844 / airline 1440×900 / fleet_ops 1440×900
- 设备像素比：2x（高 DPI 截图）
- 等待：domcontentloaded + networkidle (5s timeout) + 1.5s 动画缓冲

无 Chrome DevTools 远程调试依赖（9222 端口未启用），提升可复现性。
