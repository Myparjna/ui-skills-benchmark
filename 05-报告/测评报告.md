## 1. 项目背景

本仓库用于横向对比 **7 个 AI 模型**（Kimi 2.5、Mimo V2 Omni、Mimo V2.5、GLM、Gemini 3、Gemini 3.5、MiniMax M3）在 **前端设计 skill** 驱动下的页面生成效果。  
每个模型使用相同的 14 款公共 design skill + 各模型独占的 baseline/special skill，在 3 个产品场景（官网、小程序、后台）中生成页面，最终统一展示为可切换、可对比的 gallery 网站。

### 3.1 各目录详细说明

- **`kimi/` / `mimoV2omni/` / `glm/` / `gemini/`**  
  各模型的原始 HTML 文件。命名规则因模型而异：
  - Kimi：`{skillId}_{airline|charging|bikeops}.html`
  - Mimo：`{skillId}-{airline|ev-charging|bike-dashboard}.html`（特殊 skill 为独立命名）
  - GLM：`{prefix}_{skystar_airline|ev_charging|fleet_ops}.html`
  - Gemini：`{skillId}_{skystar_airline|ev_charging|fleet_ops}.html`

- **`showcase/pages/`**  
  所有原始 HTML 的聚合副本，供 `index.html` / `view.html` 直接引用。修改源文件后需同步复制到此目录。

- **`skills/`**  
  公共 design skill 的 SKILL.md 文件。当前包含 12 款公共 skill：
  `canvas-design`、`design-md`、`design-taste-frontend`、`frontend-design-pro`、
  `frontend-design`、`modern-frontend-design`、`nuxt-ui`、`stitch-design`、
  `ui-ux-pro-max`、`web-design-guidelines`、`sleek-design-mobile-apps`、`shadcn`。

- **`showcase/assets/screenshots/`**  
  150+ 张 PNG 截图，与 `pages/` 中的 HTML 一一对应。文件名与 HTML 文件名一致（仅扩展名改为 `.png`）。

## 4. 本地预览

`showcase/` 是一个完全自包含的静态站点，无需构建工具，直接用浏览器打开即可：

```bash
# 方法 1：直接打开
start showcase/index.html

# 方法 2：本地静态服务器（推荐，避免 iframe 跨域限制）
cd showcase
npx serve .
# 然后访问 http://localhost:3000
```

## 5. 部署方式

项目托管在 **Cloudflare Pages**。使用 Wrangler CLI 部署：

```bash
# 需要设置环境变量（非交互式部署必需）
set CLOUDFLARE_API_TOKEN=cfut_xxxxxxxxx
npx wrangler pages deploy ./showcase
```

部署成功后，会输出新的预览链接（如 `https://xxxx.frontend-design-skills-showcase.pages.dev`），生产域名始终为：  
**`https://frontend-design-skills-showcase.pages.dev`**

## 6. 维护常用操作

### 6.1 替换某个模型的页面

1. 修改源目录中的 HTML（如 `kimi/canvas-design_airline.html`）
2. 复制到 showcase：
   ```bash
   copy kimi\canvas-design_airline.html showcase\pages\
   ```
3. 重新截图（可选）：
   ```bash
   python screenshot_all.py
   # 或仅针对该模型运行对应的截图脚本
   ```
4. 重新部署：
   ```bash
   npx wrangler pages deploy ./showcase
   ```

### 6.2 批量重新截图

运行根目录下的 `screenshot_all.py`：

```bash
python screenshot_all.py
```

该脚本会遍历 `kimi/`、`mimoV2omni/`、`glm/`、`gemini/` 四个目录，按桌面端（1440×900）或移动端（390×844）自动截图并输出到 `showcase/assets/screenshots/`。

## 7. 关键代码说明

### 7.1 `showcase/index.html`

- **模型切换**：`activeModel` 控制当前展示哪个模型（`all` / `kimi` / `mimo` / `glm` / `gemini3` / `gemini35` / `mimoV25` / `m3`）
- **分类去重（全部模型模式）**：`getCurrentCategories()` 会合并 7 个模型的分类列表，同名 skill（如 `Apple Inspired`、`Linear Inspired`、`不使用skills`、`impeccable`、`taste-skill`、`modern-web-design`、`superdesign`）在 chips 中只会显示一个
- **筛选记忆**：使用 `localStorage.setItem('skillShowcaseFilters', ...)` 保存用户的模型、Tab、Chip 选择，返回展厅时自动恢复
- **页面统计**：首页顶部的 "262 个页面 · 15 种设计来源 · 3 个产品场景 · 7 个模型" 为硬编码，需随内容增减手动更新

### 7.2 `showcase/view.html`

- 通过 URL 参数 `?src=...&title=...` 加载目标页面
- 自动检测：若 `src` 包含 `charging`，则使用居中 iPhone 框架渲染；否则全屏桌面渲染

## 9. 后续建议

1. **新增模型**：若有新模型加入，按现有 7 个模型的模式新建目录 → 生成 HTML → 在 `index.html` 的 `getFileMap()` 和分类数组中注册 → 截图 → 复制到 `showcase/pages/` → 部署。
2. **新增 skill**：在 `commonCategories` 中添加公共 skill 定义，各模型按各自命名规则生成 3 个页面即可。
3. **截图维护**：Playwright 脚本依赖本地文件路径 `file:///C:/...`，迁移到新电脑时需修改 `BASE_DIR` 变量。
4. **M3 部署**：M3 加测已完成，展厅 `index.html` 已加 M3 按钮；如需推送到线上，运行 `npx wrangler pages deploy ./05-报告/展厅` 即可。
