## 1. 项目背景

本项目横向对比 **6 个 AI 模型** 在前端设计 skill 驱动下的页面生成效果。

- **测评目标**: 验证不同模型在使用相同/不同 design skill 时的页面生成质量差异
- **测评维度**: 视觉表现、设计系统一致性、响应式适配、代码质量
- **参与模型**: Kimi 2.5、Mimo V2 Omni、GLM、Gemini 3、Mimo V2.5、Gemini 3.5、MiniMax M3、DeepSeek V4、**Kimi K2.6**（新增）
- **测评技能数**: 14 款公共 design skill + 各模型独占 skill
- **测试场景**: 3 个产品场景（官网 / 小程序 / 后台）
- **总页面数**: 349 个 HTML 页面

## 9. 维护操作

### 9.1 新增模型

1. 在 `03-产出/` 下新建模型目录，生成 HTML 文件
2. 将 HTML 复制到 `05-报告/展厅/pages/`，加模型前缀避免冲突
3. 编辑 `05-报告/展厅/index.html`:
   - 添加模型按钮
   - 添加 `{model}Categories` 数组
   - 在 `getFileMap()` 中添加文件映射
   - 在 `getAllItems()` 中注册
   - 在 `modelBadgeColor()` 中添加颜色
   - 在 `renderGallery()` 中添加模型标签
   - 在 `loadFilters()` 中添加到允许列表
   - 更新 header 统计数字
4. 截图: 运行 Puppeteer 脚本
5. 部署

### 9.2 重新截图

```bash
# 安装 puppeteer（首次）
cd C:\Users\mypra\Desktop\TempScr\puppeteer-screenshot
npm install puppeteer

# 截图（默认 mimoV25 前缀）
node screenshot.js mimoV25

# 截图其他前缀
node screenshot.js kimi
node screenshot.js glm
```

截图脚本会自动启动本地 HTTP 服务器，避免 `file://` 跨域问题。

### 9.3 截图脚本说明（Puppeteer 历史方案）

脚本位于 `C:\Users\mypra\Desktop\TempScr\puppeteer-screenshot\screenshot.js`，工作流程：
1. 启动 Node.js 内置 HTTP 服务器（端口 18923）服务 `pages/` 目录
2. Puppeteer 通过 `http://localhost:18923/{file}` 访问页面
3. 使用 `networkidle0` 等待所有资源加载完成
4. 截取 1440x900 桌面端截图，输出到 `assets/screenshots/`

### 9.4 截图脚本说明（Playwright 推荐方案）

新增 Python + Playwright 截图方案，支持桌面端和移动端分别设置分辨率：

- **脚本位置**: `05-报告/展厅/screenshot_kimi_k2_6_v2.py`
- **依赖安装**:
  ```bash
  python -m pip install playwright
  python -m playwright install chromium
  ```
- **使用方式**:
  1. 先启动本地 HTTP 服务器：`python -m http.server 8766`
  2. 运行截图脚本：`python screenshot_kimi_k2_6_v2.py`
- **截图参数**:
  - 桌面端（官网/后台）: 1920x1080, `networkidle` + 2s 延迟
  - 移动端（小程序）: 414x896 @2x, `networkidle` + 2s 延迟
- **输出目录**: `assets/screenshots/`

**推荐**: 新模型加测时优先使用 Playwright 方案，支持更灵活的视口配置。
